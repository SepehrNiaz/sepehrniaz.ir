Python from absolute zero

For someone who has never programmed: what a program is, how Python reads your lines, and why the spaces at the start of a line matter — explained one small step at a time.

After this lesson you can
  • Explain what a program is and how Python reads it
  • Write print, variables, if / elif / else, for, while and def without help
  • Say exactly why and where a line must be indented, and fix an IndentationError

What is a program?

A program is a list of instructions written in a text file. The computer reads the file from the top, one line at a time, and does exactly what each line says — nothing more, and nothing it was not told. It does not guess what you meant. That sounds strict, and it is, but it is also good news: when something goes wrong, the reason is always written on the screen in front of you.

Python is one of the languages you can write those instructions in. It was designed to be read easily, which is why schools, scientists, network engineers and security teams all use it. You do not need to be good at mathematics. You need patience, and the habit of typing the examples yourself.

Open the Python tab of the practice lab in another window and type every example in this lesson. Reading teaches you about ten per cent; typing teaches the rest.

Your first line: print

Look at each piece, because every later line is built from the same pieces. print is the name of a command (Python calls it a function) that shows something on the screen. The round brackets ( ) hold what you hand to the command; they must open and close. The quotation marks " " tell Python 'this is text, show it exactly as written'. Without quotation marks Python tries to work the thing out — which is why print(2 + 3) shows 5, but print("2 + 3") shows the characters 2 + 3. A comma between two things prints both with a space between them.

  • Capital letters matter: Print and PRINT do not exist; only print does.
  • Every ( needs a ) and every " needs a second ".
  • One instruction per line. You do not put a full stop or a semicolon at the end.
  • A line that starts with # is a comment: a note for people. Python skips it.

Variables: giving a value a name

A variable is a name that points to a value, like a label on a box. You create it with a single equals sign: the name goes on the left, the value on the right. Read age = 17 as 'let age be 17', not as 'age equals 17'. That is why the second line below is not nonsense: it means 'take the current age, add one, and store the result under the same name'.

  • Choose names that explain themselves: student_count is better than sc or x.

  • A few words belong to Python and cannot be used as names: if, for, def, True, class and about thirty others.

Text and numbers are different things

"42" in quotation marks is two characters of text; 42 without them is a number you can calculate with. Python never mixes them silently, and that protects you from a whole family of mistakes. When you need to cross from one to the other, you convert on purpose: int() makes a whole number, float() a decimal number and str() text.

Asking yes-or-no questions

Programs become useful when they can decide. A decision starts with a question whose answer is True or False. Notice the double equals sign: one = stores a value, two == ask 'are these the same?'. Mixing them up is the most common beginner mistake of all.

if — and why the next line must start with spaces

This is the part that confuses nearly everyone at first, so we will go slowly. An if statement has two parts. The first line asks the question and ends with a colon. The colon means 'what follows belongs to me'. The lines after it that are pushed to the right — indented, by four spaces — are the lines that run only when the answer is True. Together they are called a block.

Why spaces? Python needs some way to know where the 'only if true' part begins and ends. Many other languages use curly brackets { } for this and treat the spaces as decoration. Python's designer chose the spaces themselves as the rule, because good programmers indent their code anyway — so in Python, the way the code looks is the way it works. The spaces are not style. They are grammar. Move a line four spaces to the left and you have changed what the program does.

Here is what Python says when you forget — first the spaces, then the colon. Read both messages: they tell you the line number and exactly what was expected.

  • The rule in one sentence: a line that ends with a colon is always followed by an indented block.
  • This holds for every such line: if, elif, else, for, while, def, class, try, except and with.
  • Use four spaces for each level. Every line of the same block must have exactly the same number.
  • Do not mix the Tab key and spaces in one file. Good editors — and the practice lab — type four spaces when you press Tab.
  • The block ends at the first line that goes back to the left. There is no 'end' word.

else, elif and blocks inside blocks

else is the 'otherwise' branch: it runs when the question was False. elif (short for 'else if') asks another question when the first one failed. A block can contain another if, and then that inner block is indented by four more spaces — eight in total. You can always tell which if a line belongs to by looking straight up from its first character.

Repeating: for and while

A loop runs the same block several times. for takes the items of a collection one by one; range(1, 4) produces the numbers 1, 2 and 3 — the last number is not included. The loop line ends with a colon, so the lines that repeat are indented, exactly as with if.

Functions: def, and the same rule about spaces

A function is a block of code with a name, so that you can use it again without writing it again. You define it with def. Look at the first line piece by piece: def says 'I am defining a function', greet is the name you chose, name inside the brackets is a parameter — a variable that receives whatever is handed in — and the colon at the end, as always, announces a block. So the lines of the function are indented by four spaces. Everything indented under def is the function; the first line that returns to the left margin is outside it.

Reading an error message

Errors are the normal state of programming, not a sign that you are bad at it. Professionals see dozens every day. The difference is only that they read the message calmly: which line, what kind of error, what was expected. Python often even suggests the fix, as it did here.

Putting it all together

Common mistakes

  • Forgetting the colon at the end of if, else, for, while or def.
  • Not indenting the line after a colon — or indenting some lines of a block by 4 spaces and others by 3.
  • Writing = when asking a question. if age = 18 is an error; it must be if age == 18.
  • Forgetting the quotation marks, so Python looks for a variable called Sara.
  • Using print inside a function when you meant return.

Exercises

Try each one yourself first, then open the answer.

  1. What does this print, and why? x = 5 if x > 10: print("big") print("end")

    Only: end
x > 10 is False, so the indented line is skipped. print("end") is not indented, so it is outside the if.

  2. Find the two mistakes: def double(n) return n * 2

    Show the answer
    The colon after def double(n) is missing, and return must be indented by four spaces:

def double(n):
    return n * 2

  3. Write a program that prints the numbers 1 to 10 and, next to each, the word even or odd. (Hint: n % 2 is 0 for even numbers.)

    Show the answer
    for n in range(1, 11):
    if n % 2 == 0:
        print(n, "even")
    else:
        print(n, "odd")

  4. Write a function biggest(a, b) that returns the larger of two numbers, and print biggest(7, 12).

    Show the answer
    def biggest(a, b):
    if a > b:
        return a
    else:
        return b

print(biggest(7, 12))

  5. Why does print("10" + 5) fail, and what are two ways to fix it?

    Show the answer
    "10" is text and 5 is a number. Either make both numbers — print(int("10") + 5) gives 15 — or both text — print("10" + str(5)) gives 105.

Practise this in the lab

Remember
  • Python reads top to bottom, one instruction per line.
  • A colon at the end of a line promises a block; the block is the lines indented by four spaces under it.
  • = stores, == asks. Text lives in quotation marks.
  • def makes a function, return gives its answer back.
  • Read errors from the bottom line up.
