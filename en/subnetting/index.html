Subnetting step by step

Why networks are split, the one method that solves every subnetting question by hand, and how to plan addresses for a whole building.

After this lesson you can
  • Find the network, broadcast and usable range of any address by hand
  • Decide whether two addresses are on the same network
  • Plan subnets of different sizes for several departments

Why split a network at all?

Imagine a hotel where the reception computers, two hundred guest phones, sixty cameras and the accounting server all share one network. Three problems appear. Every device hears every other device's broadcast messages, so the network gets noisy and slow. A guest's infected laptop can reach the accounting server directly. And when something breaks, you have one huge group of addresses to search. Subnetting cuts one large network into several smaller ones, each with its own range of addresses, so that traffic between them must pass through a router or firewall where you can control it.

This lesson builds on 'What is an IP address?'. If the words prefix, mask and broadcast are new to you, read that lesson first.

The only numbers you need to memorise

  • Device bits = 32 − prefix.
  • Block size = 2 to the power of the device bits.
  • Usable devices = block size − 2 (the first address names the network, the last is the broadcast).
  • Last number of the mask = 256 − block size.

The method: find the block

Every subnetting question — 'what is the network of this address?', 'what is its broadcast?', 'are these two on the same network?' — is solved the same way. Work out the block size, list where the blocks start (multiples of the block size), and see which block the address falls into.

Example: 192.168.1.130/26. The prefix is 26, so there are 6 device bits and the block size is 64. Blocks start at 0, 64, 128 and 192. The number 130 lies between 128 and 191, so the network is 192.168.1.128, the broadcast is 192.168.1.191 (one below the next block), and the usable addresses run from .129 to .190.

Are two devices on the same network?

Find the network of each. If they match, the devices talk directly; if not, they need a router. With a /26 mask, 192.168.1.60 is in the block starting at 0 and 192.168.1.70 is in the block starting at 64 — different networks, although the numbers look close. This is the calculation every device does before sending a single packet, and a wrong mask on one device is a classic reason for 'I can ping some machines but not others'.

Different sizes for different needs: VLSM

Departments are never the same size, and giving each one a /24 wastes addresses. VLSM (variable-length subnet masks) means choosing a different prefix for each. The rule that keeps it tidy: start with the largest need and work down, placing each block directly after the previous one.

Task: from 192.168.10.0/24, plan Rooms (100 devices), Reception (50), Cameras (25) and a link between two routers (2).

When the block is bigger than 256

For prefixes shorter than /24 the same method moves one number to the left. In /22 there are 10 device bits: 2 of them are in the third number, so the third number moves in blocks of 4, and the fourth number is free from 0 to 255. So 172.16.5.9/22 belongs to the network 172.16.4.0, its broadcast is 172.16.7.255, and it holds 1022 devices.

For professionals

  • Summarisation is subnetting backwards: 192.168.0.0/24 to 192.168.3.0/24 can be advertised as one route, 192.168.0.0/22, which keeps routing tables small.
  • The wildcard mask used in Cisco ACLs and OSPF is the mask turned inside out: 255.255.255.192 becomes 0.0.0.63.
  • A /31 has no network or broadcast address and is allowed on point-to-point links (RFC 3021); a /32 names a single host.
  • Leave room to grow: plan each subnet for about twice the devices it has today.
  • Write the plan down — subnet, VLAN number, gateway, purpose — before you configure anything.

Common mistakes

  • Forgetting to subtract 2 for the network and broadcast addresses.
  • Giving a device the network address or the broadcast address.
  • Starting a block at a number that is not a multiple of its size.
  • Planning the small subnets first, which leaves gaps.

Exercises

Try each one yourself first, then open the answer.

  1. Find the network and broadcast of 192.168.5.100/27.

    Show the answer
    Block size 32 → blocks at 0, 32, 64, 96, 128. 100 is in the block starting at 96.
Network 192.168.5.96, broadcast 192.168.5.127, usable .97 – .126.

  2. You need a subnet for 40 devices. Which prefix?

    Show the answer
    /26 — 62 usable addresses. A /27 has only 30.

  3. With mask 255.255.255.240, are 10.1.1.17 and 10.1.1.30 on the same network?

    Show the answer
    Yes. The block size is 16; both fall in the block 16–31 (network 10.1.1.16).

  4. From 10.0.0.0/24, plan subnets for 60, 28 and 10 devices.

    Show the answer
    60 → 10.0.0.0/26 (.1 – .62)
28 → 10.0.0.64/27 (.65 – .94)
10 → 10.0.0.96/28 (.97 – .110)

Practise this in the lab

Remember
  • Block size = 2^(32 − prefix); blocks start at its multiples.
  • Network = start of the block; broadcast = one below the next block.
  • Usable = block size − 2.
  • Plan largest first.
