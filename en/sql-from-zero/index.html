SQL from zero: asking questions of data

What a database and a table are, and how to read, filter, sort, count, change and join data with SQL — every command explained word by word, with real output.

After this lesson you can
  • Explain what a table, a row, a column and a primary key are
  • Read data with SELECT, WHERE, ORDER BY and LIMIT
  • Summarise with COUNT, AVG and GROUP BY, and connect two tables with JOIN
  • Change data safely with INSERT, UPDATE and DELETE

What is a database?

A database is an organised place to keep information so that it can be found again quickly. Think of a spreadsheet: a table has columns (name, city, grade) and rows (one row for each student). A database is a collection of such tables, kept by a program that can search millions of rows in a moment and let many people use them at once. Almost every app you use — a shop, a bank, a messaging service — keeps its information this way.

SQL (say 'sequel' or 'S-Q-L') is the language for talking to that program. It is not a general programming language like Python: it does one thing — describe the data you want — and it reads almost like English. The same SQL works, with small differences, in SQLite, MySQL, PostgreSQL and Microsoft SQL Server. This lesson uses SQLite, which is also what the SQL tab of the practice lab runs.

  • SQL words such as SELECT can be written in capitals or small letters. Capitals are a habit that makes them stand out.
  • Every statement ends with a semicolon ;
  • Text values go inside single quotation marks: 'Shiraz'. Numbers have no quotation marks.
  • Spaces and line breaks do not matter; break long statements over several lines to make them readable.

Making a table: CREATE TABLE

Read it piece by piece. CREATE TABLE students makes a new, empty table called students. Inside the brackets is one line per column: its name, then the type of value it holds. INTEGER is a whole number and TEXT is text. PRIMARY KEY marks the column that identifies each row uniquely — the database fills in 1, 2, 3 by itself. NOT NULL means 'this column may not be left empty'.

Adding rows: INSERT

Reading: SELECT

SELECT is the command you will use ninety per cent of the time. Its shape is: SELECT which columns FROM which table. A star means 'all columns'.

Filtering: WHERE

WHERE keeps only the rows for which a condition is true. Note that SQL uses a single = to compare — unlike Python's ==.

ConditionMeaning
grade = 20exactly 20
grade <> 20not 20 (also written !=)
grade BETWEEN 10 AND 15from 10 to 15, both included
city IN ('Shiraz', 'Tehran')any value in the list
name LIKE '%a'ends with a
city IS NULLthe column is empty (never write = NULL)
NOT, AND, ORcombine conditions; use brackets when you mix AND with OR

Sorting and limiting: ORDER BY, LIMIT

A table has no fixed order of its own. If the order matters, always say ORDER BY.

Counting and averaging

One answer per group: GROUP BY

GROUP BY city sorts the rows into piles, one pile per city, and then the counting functions give one answer for each pile. This single idea produces most of the reports in the world: sales per month, tickets per department, failed logins per address.

Changing and deleting: UPDATE, DELETE

UPDATE and DELETE without WHERE act on every row in the table, and there is no undo. Write the WHERE first; better still, run the same condition as a SELECT first to see which rows will be touched.

Connecting tables: JOIN

Real databases split information over several tables so that nothing is written twice. Here a second table, courses, stores which student takes which course by keeping the student's id — not the name. A JOIN puts the two tables side by side wherever the ids match.

The ON part is the rule for matching: 'a course belongs to the student whose id equals the course's student_id'. Writing table.column (students.name) says which table a column comes from, which is required when both tables have a column with the same name, such as id.

The order SQL thinks in

You write SELECT first, but the database does not start there. Knowing the real order explains most confusing errors — for example, why you cannot use a name made with AS inside WHERE.

StepClauseWhat happens
1FROM / JOINChoose and connect the tables
2WHEREThrow away rows that don't match
3GROUP BYSort the remaining rows into groups
4HAVINGThrow away groups that don't match
5SELECTPick the columns and calculate
6ORDER BYSort the result
7LIMITKeep the first rows

Reading SQL errors

For professionals: keeping data safe and fast

  • Never build SQL by gluing in text that a user typed. That is how SQL injection — one of the most common attacks on websites — works. Use placeholders instead: in Python, db.execute("SELECT * FROM students WHERE name = ?", (name,)) .
  • An index is like the index at the back of a book: CREATE INDEX idx_city ON students(city); makes searches on that column fast, at the cost of slightly slower inserts.
  • A transaction groups several changes so that either all happen or none: BEGIN; … COMMIT; (or ROLLBACK; to cancel). Banks depend on it.
  • A foreign key tells the database that courses.student_id must point to a real student, so it refuses orphaned rows.
  • Back up the database before every risky change. For SQLite the whole database is one file you can copy.

Common mistakes

  • Forgetting the semicolon, so the database waits for more.
  • Double quotation marks or no quotation marks around text: write 'Shiraz'.
  • DELETE or UPDATE without WHERE.
  • Writing = NULL instead of IS NULL.
  • Selecting a column that is neither in GROUP BY nor inside a function such as COUNT.

Exercises

Try each one yourself first, then open the answer.

  1. Show the name and city of every student, sorted by name.

    Show the answer
    SELECT name, city FROM students ORDER BY name;

  2. Show the students from Tehran or Isfahan whose grade is at least 15.

    Show the answer
    SELECT * FROM students
WHERE city IN ('Tehran', 'Isfahan') AND grade >= 15;

  3. Which city has the highest average grade? Show only that one row.

    Show the answer
    SELECT city, AVG(grade) AS average FROM students
GROUP BY city ORDER BY average DESC LIMIT 1;

  4. Add one point to the grade of every student in Shiraz.

    Show the answer
    UPDATE students SET grade = grade + 1 WHERE city = 'Shiraz';

  5. List each course title with the number of students taking it.

    Show the answer
    SELECT title, COUNT(*) AS students FROM courses GROUP BY title;

Practise this in the lab

Remember
  • A table is rows and columns; SQL describes the rows you want.
  • SELECT columns FROM table WHERE condition ORDER BY column LIMIT n;
  • GROUP BY makes one row per group; JOIN … ON connects tables through ids.
  • No WHERE on UPDATE or DELETE means every row.
  • Never glue user input into SQL — use placeholders.
