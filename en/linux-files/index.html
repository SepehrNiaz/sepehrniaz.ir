Files and folders on the command line

List, create, move and delete files without a mouse — the handful of commands you'll use every single day.

After this lesson you can
  • Move around the folder tree with cd and ls
  • Create, copy, rename and delete files and folders
  • Tell a relative path from an absolute one

Everything in Linux is a file, and you spend most of your time moving between folders and looking at what's inside them. Six commands cover almost all of it: ls, cd, mkdir, touch, cp, mv and rm. Let's build a small workspace and use each one.

Looking: ls

ls lists what's in the current folder. Add -l for a detailed list (permissions, owner, size, date) and you see the real shape of each item — a dash means a file, a d means a directory.

Making things: mkdir and touch

mkdir makes a new directory; touch creates an empty file (or updates its timestamp). cd moves you into a folder, and cd .. moves you back up one level.

Copy, move, rename, delete

  • cp a.txt b.txt — copy a file
  • mv a.txt docs/ — move it into another folder
  • mv old.txt new.txt — rename (move onto a new name)
  • rm file.txt — delete a file
  • rm -r folder — delete a folder and everything in it
rm deletes permanently — there is no Recycle Bin on the command line. Read the line twice before you press Enter, especially with rm -r.

A trick that saves your fingers

Start typing a file or folder name and press Tab. The shell completes it for you. Press Tab twice to see all the matching options. You'll use this thousands of times.

The map of a Linux system

Windows has drives such as C: and D:. Linux has a single tree that starts at one point called the root, written as a lone slash: / . Every disk, USB stick and folder hangs somewhere under it. A few folders exist on every Linux system, and knowing them tells you where to look.

FolderWhat lives there
/homeOne folder per user: your documents and settings.
/etcSettings of the system and of installed programs, as text files.
/var/logLog files: the diary of the system. The first place to look when something breaks.
/tmpTemporary files. Emptied when the machine restarts.
/usr/binThe programs you run, such as ls and python3.
/rootThe home folder of the administrator.
/dev, /procNot real files: windows onto devices and running processes.

Reading what is inside a file

Most things on Linux are plain text, so reading files is half of the job. Pick the tool by the size of the file.

  • less file opens a long file one screen at a time: Space for the next page, /word to search, q to quit.
  • tail -f /var/log/syslog keeps the file open and shows new lines as they arrive. This is how you watch a log live; stop with Ctrl+C.
  • Never cat a huge file or a program file — use less, or head first to see what it is.

Writing into files

The > sign sends what a command prints into a file instead of the screen. One > replaces the file; two >> add to its end. Mixing them up is one of the classic ways to lose data, so read the line before you press Enter.

To edit a file properly, use an editor. nano is the friendliest: nano notes/todo.txt opens the file, you type as usual, Ctrl+O then Enter saves, and Ctrl+X leaves. The other common editor, vim, is powerful but has its own rules; if you open it by accident, press Esc, type :q! and press Enter to get out.

Finding files and finding text

Two different questions need two different tools. find looks for files by name, type, size or age. grep looks inside files for a piece of text.

  • grep -i ignores capital letters; grep -n shows line numbers; grep -v shows the lines that do NOT match.
  • find /var/log -mtime -1 lists files changed in the last day.
  • find . -size +100M finds the big files that are filling your disk.
  • Join commands with a pipe: grep Failed logs/auth.log | wc -l counts the failed logins. The | sign hands the output of the left command to the right one.

Many files at once: wildcards

The shell can fill in file names for you. A star stands for any number of characters and a question mark for exactly one. So *.txt is every text file, report-202?.pdf matches report-2025.pdf and report-2026.pdf, and backup* is everything that starts with backup. The shell expands the pattern before the command runs, which means rm * really does mean 'delete everything here'. Test a pattern with ls first, then reuse it with rm.

How big is it?

When a disk fills up, the hunt is always the same: df -h to see which disk, then du -sh /var/* | sort -h to see which folder is the biggest, then go one level deeper and repeat.

Packing folders: tar

To unpack, swap c for x: tar -xzf notes-backup.tar.gz . Add -C /some/folder to unpack somewhere else. This one command is how most backups and software downloads on Linux are packed.

Paths: the address of a file

An absolute path starts with / and works from anywhere, like /home/student/notes/todo.txt. A relative path starts from where you are now, like notes/todo.txt. Three shortcuts are worth memorising: a single dot is this folder, two dots is the folder above, and ~ is your home.

  • cd .. goes up one level; cd ~ goes home; cd - returns to the previous folder.
  • ls -la also shows hidden files — the ones whose names start with a dot.
  • mkdir -p a/b/c creates the whole chain of folders in one go.
  • cp -r copies a folder with everything inside; rm -r deletes one the same way.
  • A star matches many names: ls *.txt lists every file ending in .txt.

Common mistakes

  • Running rm without checking where you are. Run pwd and ls first.
  • Names with spaces: write "my file.txt" in quotes, or the shell sees two names.
  • Using mv onto an existing name — it replaces that file without asking.

Exercises

Try each one yourself first, then open the answer.

  1. Create a folder called lab and, inside it, an empty file called notes.txt.

    Show the answer
    mkdir lab
cd lab
touch notes.txt

  2. Rename notes.txt to todo.txt.

    Show the answer
    mv notes.txt todo.txt

  3. You are in /home/student/lab. Which folder does cd ../.. take you to?

    Show the answer
    /home  (up two levels)

  4. Make a backup copy of the whole lab folder called lab-backup.

    Show the answer
    cp -r lab lab-backup

Practise this in the lab

Remember
  • ls looks, cd moves, mkdir and touch create.
  • cp copies, mv moves or renames, rm deletes for good.
  • / starts an absolute path; .. is up; ~ is home.
