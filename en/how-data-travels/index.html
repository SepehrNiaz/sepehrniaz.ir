How data travels: switch, router, DNS and DHCP

What each box in a network really does, the layers that data is wrapped in, and the full journey of one request from your browser to a server and back.

After this lesson you can
  • Explain the difference between a switch and a router
  • Describe what ARP, DNS and DHCP each do
  • Follow one request from the browser to the server, naming each step

A letter in an envelope in a van

Data does not travel as one piece. It is cut into small packets, and each packet is wrapped several times, like a letter put into an envelope, the envelope put into a postbag, and the bag loaded onto a van. Each wrapping has its own job and its own address. Networking is organised into these layers so that each part can change without the others noticing: you can swap Wi-Fi for a cable, and your browser never knows.

You will also hear of the seven-layer OSI model. It describes the same thing in more detail: its layers 1 and 2 are the link, layer 3 is the network, layer 4 the transport and layers 5 to 7 the application. When an engineer says 'a layer 2 problem' they mean switches and MAC addresses; 'layer 3' means IP addresses and routing.

The switch: delivering inside one network

A switch connects the devices of one network. It works with MAC addresses only. When a frame arrives on a port, the switch notes 'this MAC address lives on this port' in a table. To deliver a frame it looks up the destination MAC and sends the frame out of that one port. If it does not know the address yet, it sends the frame out of every port and learns from the reply. This learning is automatic — which is why a simple switch works the moment you plug it in.

ARP: from IP address to MAC address

Your computer knows the IP address it wants to reach, but the switch needs a MAC address. So the computer shouts to the whole network: 'who has 192.168.1.1? Tell 192.168.1.24.' The owner answers with its MAC address, and the computer remembers the pair for a few minutes. That question is ARP. You can see what your computer has learned with arp -a on Windows or ip neigh on Linux.

The router: moving between networks

A router connects different networks and works with IP addresses. It has one foot in each network and a routing table that says, for each destination network, which way to send the packet. For everything it has no specific rule for, it uses the default route — 'send it to my own upstream router'. Your home router's table is tiny: the home network on one side, and 'everything else' towards the internet provider.

DNS: the phone book

People remember names; networks need numbers. DNS turns sepehrniaz.ir into an IP address. Your computer asks the DNS server it was given (often the router, which asks your provider's server). If that server does not know, it asks its way down a chain: the root servers know who handles .ir, the .ir servers know who handles sepehrniaz.ir, and that last server gives the answer. The result is kept (cached) for a while, so the next visit is instant.

DHCP: getting set up automatically

A device needs four settings to use a network: an IP address, a mask, a gateway and a DNS server. Typing them into every phone would be impossible, so a DHCP server — usually the router — hands them out. The device asks, the server offers an address from its pool, the device accepts and the server confirms. The address is lent for a limited time (the lease) and renewed in the background. Devices that others must always find at the same address — servers, printers, cameras — should get a fixed address outside the pool, or a reservation tied to their MAC address.

The whole journey, step by step

  • You type sepehrniaz.ir. The browser asks DNS and receives an IP address.
  • The computer compares that address with its own network. It is elsewhere, so the packet must go to the gateway.
  • ARP finds the gateway's MAC address. The packet is wrapped in a frame addressed to that MAC.
  • The switch reads the MAC address and passes the frame to the router's port.
  • The router unwraps the frame, reads the IP address, replaces your private address with its public one (NAT), wraps the packet in a new frame and sends it to the provider.
  • Router after router repeats this: new frame at every hop, same IP packet inside.
  • The server receives the packet; TCP hands it to the web server program on port 443.
  • The answer returns the same way, and the router's NAT table sends it to your computer.

Notice the pattern: the IP addresses stay the same for the whole journey (apart from NAT), while the MAC addresses change at every hop. That one sentence is the heart of networking.

Common mistakes

  • Thinking a switch and a router are the same box with different prices.
  • Blaming 'the internet' when only DNS is failing.
  • Giving a printer an address from the DHCP pool by hand — later the server gives the same address to a phone.
  • Plugging a second home router's LAN port into the network: its DHCP server starts handing out wrong settings.

Exercises

Try each one yourself first, then open the answer.

  1. Two computers are on the same switch with addresses 192.168.1.10/24 and 192.168.2.10/24. Can they talk without a router? Why?

    Show the answer
    No. They are in different IP networks, so each sends its packets to its gateway. Without a router between the two networks nothing arrives.

  2. Which address changes at every hop, and which stays the same?

    Show the answer
    The MAC addresses change at every hop; the IP addresses stay the same from end to end (except where NAT rewrites them).

  3. A user can open 142.250.74.14 in the browser but not google.com. What is broken?

    Show the answer
    DNS. The path works; names are not being resolved. Check the DNS server setting.

  4. Which four settings does DHCP give a device?

    Show the answer
    IP address, subnet mask, default gateway and DNS server (plus the lease time).

Practise this in the lab

Remember
  • Switch: one network, MAC addresses. Router: between networks, IP addresses.
  • ARP finds a MAC for an IP; DNS finds an IP for a name; DHCP gives the settings.
  • IP addresses stay, MAC addresses change at every hop.
