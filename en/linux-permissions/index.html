Understanding file permissions

That rwxr-xr-x string next to every file isn't noise — it's who can read, write and run it. Learn to read and change it.

After this lesson you can
  • Read the ten permission characters of ls -l
  • Change permissions with chmod, with letters and with numbers
  • Choose safe permissions for private files and scripts

Linux was built from day one to be used by many people at once, so every file carries permissions: who is allowed to read it, change it, or run it. Getting this right is the difference between a secure server and one that anyone can tamper with.

Reading the ten characters

In ls -l, the first column looks like -rw-r--r--. The first character is the type (- file, d folder). The next nine are three groups of three: the owner, the group, and everyone else. In each group, r = read, w = write, x = execute, and a dash means “not allowed”.

The number shortcut

You'll often see chmod 755 or chmod 644. Each digit is one group (owner, group, others), where read=4, write=2, execute=1 are added up. So 7 = rwx, 6 = rw-, 5 = r-x, 4 = r--. 755 means the owner can do everything and others can read and run — the standard for a program.

A private key or password file should be 600 (owner read/write, nobody else anything). If SSH refuses your key, wrong permissions are almost always the reason.

Why permissions exist

Linux was built for machines that many people share. Permissions answer one question for every file: who is allowed to do what? They are the first wall of defence on any server. A website that is hacked can only damage what its own user may touch; a private key that everyone can read is no longer private. Most real break-ins are not clever — they walk through a permission that was left too open.

Users and groups

Every file has one owner and one group. Every user has a number (the UID), belongs to one or more groups, and has a line in the file /etc/passwd. The administrator, root, is always UID 0.

Seeing and setting permissions as numbers

NumberLettersTypical use
644rw-r--r--Ordinary files and web pages
640rw-r-----Settings that contain passwords
600rw-------SSH private keys, personal secrets
755rwxr-xr-xPrograms, scripts and normal folders
750rwxr-x---A folder for one team
700rwx------A private folder such as ~/.ssh

Folders are different

The three letters mean something else on a folder. r lets you list the names inside. w lets you create, rename and delete files inside — even files that belong to someone else. x lets you enter the folder and reach what is in it. A folder with r but without x is almost useless: you can see the names but open nothing. This is why folders are normally 755 or 750, never 644.

Changing the owner: chown

Where default permissions come from: umask

New files do not get random permissions. The system starts from 666 for files and 777 for folders and removes whatever the umask says. With the usual umask of 022, files become 644 and folders 755. On a server that holds private data, a umask of 027 is safer: new files become 640 and folders 750, so 'others' get nothing by default.

Three special marks

  • Sticky bit (t) on a folder: everyone may create files, but each person can delete only their own. That is why /tmp is safe to share.
  • setuid (s on the owner): the program runs with the power of its owner. passwd needs it to change your password in a file only root may write.
  • setgid (s on the group) on a folder: new files inherit the folder's group — ideal for a team folder.
  • Because setuid programs run as root, attackers look for them. List them with find / -perm -4000 -type f 2>/dev/null and question every one you do not recognise.

A worked example: a shared team folder

The support team needs one folder where every member can read and write, new files belong to the team automatically, and nobody outside the team can look in.

When 'Permission denied' appears

  • Who am I? Run whoami and id.
  • What does the file allow? Run ls -l on the file.
  • Can I reach it? Run ls -ld on every folder in the path — one folder without x blocks everything below it.
  • Fix the smallest thing: add the user to the right group, or give the group the one right that is missing.
  • Only then consider sudo — and never answer the problem with chmod 777.

Working out the numbers yourself

Each permission has a value: read is 4, write is 2 and execute is 1. Add them up for each of the three groups — owner, group, others. So rwx is 4+2+1 = 7, r-x is 4+1 = 5 and r-- is 4. That is why 754 means: the owner can do everything, the group can read and run, everyone else can only read.

  • 644 — a normal file: you edit it, others read it.
  • 755 — a script or program: you edit it, everyone may run it.
  • 600 — a private file such as an SSH key: only you.
  • 700 — a private folder: only you can enter it.
  • On a folder, x means 'may enter' and w means 'may create and delete files inside'.
  • chown changes the owner of a file; it normally needs sudo.

Common mistakes

  • chmod 777 to 'make it work'. It lets everyone change the file — find the real cause instead.
  • Forgetting chmod +x on a new script, then wondering about 'Permission denied'.
  • Using sudo for everything. Use it only when a task really needs the administrator.

Exercises

Try each one yourself first, then open the answer.

  1. What does -rw-r----- allow?

    Show the answer
    Owner: read and write. Group: read. Others: nothing. As a number: 640.

  2. Write the number for rwxr-xr-x.

    Show the answer
    755

  3. Make backup.sh runnable, then run it.

    Show the answer
    chmod +x backup.sh
./backup.sh

  4. SSH says your private key is 'too open'. Which command fixes it?

    Show the answer
    chmod 600 ~/.ssh/id_ed25519   (use the name of your own key file)

Practise this in the lab

Remember
  • Three groups (owner, group, others) × three rights (read, write, execute).
  • r=4, w=2, x=1 — add them per group.
  • Give the least permission that still works.
