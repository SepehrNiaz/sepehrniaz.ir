Text tools and pipes: answers from any file

grep, cut, sort, uniq, wc, tr, sed and awk — and the pipe that joins them. Learn to turn a raw log into an answer with one line.

After this lesson you can
  • Join commands with a pipe and read the result of each step
  • Pick lines with grep, columns with cut and awk, and count with sort | uniq -c
  • Save results and errors to files with >, >> and 2>

The idea: small tools, joined together

Linux does not have one giant program for analysing text. It has many small ones, each doing a single job well: one finds lines, one cuts columns, one sorts, one counts. The power comes from joining them. Each tool reads text, changes it a little and passes it on, like workers on a production line. Once you know eight of these tools, you can answer questions about any log, list or export file without opening a spreadsheet.

All the examples use two small files. auth.log is a login log with one event per line, and staff.csv is a list with commas between the fields.

The pipe: |

The vertical bar is called a pipe. It takes everything the command on its left prints and feeds it to the command on its right, instead of showing it on the screen. Read it as 'and then'.

grep: keep the lines that match

cut and awk: take one column

cut splits each line at a separator and keeps the fields you ask for: -d sets the separator and -f the field numbers. It is perfect for tidy files such as CSV.

Log lines are separated by a varying number of spaces, where cut struggles. awk handles them: it splits every line into words automatically and names them $1, $2, $3 …; $NF is always the last word. awk can also test a condition before printing.

sort and uniq: order and count

sort puts lines in order. uniq removes repeated lines — but only when they are next to each other, which is why it nearly always follows sort. With -c, uniq writes how many times each line appeared. A final sort -rn puts the biggest number first. This four-part chain is the most useful sentence in all of log analysis.

  • sort -n sorts as numbers (so 9 comes before 10); -r reverses; -u removes duplicates.
  • sort -t, -k2 sorts a CSV by its second field.
  • sort | uniq -c | sort -rn | head -5 gives a 'top five' of anything.

tr and sed: change the text

  • s/old/new/g replaces every occurrence on a line, not only the first.
  • sed -n '5,10p' file prints only lines 5 to 10.
  • sed -i 's/old/new/g' file changes the file itself. Make a copy first — there is no undo.

Sending output to a file: redirection

Every command has two output channels: normal results, and error messages. > sends the normal results to a file, >> adds to a file, and 2> sends the errors. This lets you keep a clean result while collecting the errors somewhere else — or throw them away by sending them to /dev/null, the system's bottomless bin.

Building a pipeline step by step

Nobody writes a long pipeline in one go. You add one tool, look at the output, then add the next. Question: at which hours of the day do logins happen?

  • cat auth.log — look at the data. The time is the third word.
  • … | awk '{print $3}' — keep only the time: 09:12:01.
  • … | cut -d: -f1 — keep only the hour, the part before the first colon.
  • … | sort | uniq -c — count each hour.

For professionals

  • journalctl -u ssh --since "1 hour ago" reads the system journal on modern Linux; pipe it into the same tools.
  • tail -f file | grep --line-buffered Failed watches a log live and shows only what matters.
  • xargs turns lines into arguments: find . -name "*.tmp" | xargs rm .
  • tee writes to a file and to the screen at once: command | tee result.txt .
  • For JSON logs use jq; for anything larger than a few gigabytes, look at ripgrep (rg), which is much faster than grep.
  • When a pipeline grows past one line, move it into a script — the next lesson on the path.

Common mistakes

  • Using uniq without sort first — repeated lines that are not neighbours are not merged.
  • Sorting numbers without -n, so 10 comes before 9.
  • Using > when you meant >>, and wiping the file.
  • Writing awk programs in double quotes, so the shell replaces $1 before awk sees it. Use single quotes.

Exercises

Try each one yourself first, then open the answer.

  1. How many successful logins are in auth.log?

    Show the answer
    grep -c Accepted auth.log

  2. List the user names that logged in successfully, each once. (The name is the 9th word.)

    Show the answer
    grep Accepted auth.log | awk '{print $9}' | sort -u

  3. Which user name was attacked most often?

    Show the answer
    grep Failed auth.log | awk '{print $9}' | sort | uniq -c | sort -rn | head -1

  4. Save the names and extensions of the Reception staff into reception.txt.

    Show the answer
    awk -F, '$2 == "Reception" {print $1, $3}' staff.csv > reception.txt

Practise this in the lab

Remember
  • | means 'and then'.
  • grep picks lines, cut and awk pick columns, sort orders, uniq -c counts.
  • sort | uniq -c | sort -rn is the top-N pattern.
  • > replaces, >> adds, 2> catches errors.
