Firewalls and hardening

How a firewall decides, how to write rules that mean what you intend, and a practical checklist for making a server, a Windows PC and a network harder to attack.

After this lesson you can
  • Explain how a firewall matches a packet against its rules
  • Write a default-deny rule set for a server
  • Harden a Linux server, a Windows PC and network devices with a checklist

What a firewall does

A firewall is a guard at a door. Every packet that wants to pass is compared with a list of rules, from the first rule down, and the first rule that matches decides: let it through, or throw it away. A rule looks at a few facts about the packet — where it comes from, where it is going, which protocol and which port. That is all. A firewall does not understand whether the content is good or bad; it only knows who may talk to whom, on which door.

#SourceDestinationPortAction
1anywhereweb server443 TCPallow
2office networkweb server22 TCPallow
3web serverdatabase3306 TCPallow
4anywhereanywhereanydeny

Read the table aloud: the world may reach the website; only the office may reach SSH; only the web server may reach the database; and everything else is refused. The last line is the most important idea in this lesson — default deny. You do not list what is forbidden, because you can never think of everything. You list the few things that are needed and forbid the rest.

  • Order matters: a broad 'allow' above a narrow 'deny' makes the deny useless.
  • Stateful firewalls remember conversations. If your computer started a connection, the answers are let back in automatically — you only write rules for who may start.
  • Inbound means arriving at the machine; outbound means leaving it. Most rule sets control inbound strictly; controlling outbound as well stops malware from calling home.
  • A host firewall protects one machine (ufw, Windows Firewall); a network firewall protects everything behind it. Use both.

A firewall on Linux in five lines

ufw is a friendly layer over the kernel's own firewall (nftables, formerly iptables). On Windows the same ideas live in 'Windows Defender Firewall with Advanced Security', with separate lists for inbound and outbound rules and three profiles — domain, private and public. A laptop on café Wi-Fi should be on the public profile, which hides it from its neighbours.

Hardening: removing what an attacker could use

Systems are delivered to be easy, not safe: services you will never use are switched on, default passwords are set, and everything is allowed. Hardening is the unglamorous work of switching off what is not needed and tightening what is. The idea behind every item below is the same — a smaller target. A service that is not running cannot be attacked; an account that does not exist cannot be stolen.

Layers: no single wall

No defence is perfect, so professionals never rely on one. They stack them, so that an attacker who passes one meets the next: a firewall at the edge, separate VLANs inside, a firewall on each machine, strong logins, least privilege, updates, logs that someone reads, and backups for when everything else has failed. This is called defence in depth. When you review a system, ask of every layer: 'if this one failed tomorrow, what would stop the attacker next?'. If the answer is 'nothing', you have found your next job.

Check your own work

  • From outside your network, scan your own public address and compare the open ports with the list you intended. The Port Scanner in the Tools section is enough for this.
  • From the guest Wi-Fi, try to reach a staff computer and the router's admin page. Both should fail.
  • Read the firewall's log of blocked packets once a week; it shows who is knocking.
  • Repeat after every change — a firewall rule added 'for a moment' is the most common hole there is.

Common mistakes

  • An 'allow everything' rule left in from testing.
  • Rules in the wrong order.
  • Trusting the network firewall alone and leaving host firewalls off.
  • Hardening once and never checking again.

Exercises

Try each one yourself first, then open the answer.

  1. Write ufw rules for a server that should offer only a website (443) to everyone and SSH to the address 192.168.1.10.

    Show the answer
    sudo ufw default deny incoming
sudo ufw allow from 192.168.1.10 to any port 22 proto tcp
sudo ufw allow 443/tcp
sudo ufw enable

  2. Rule 1 says 'allow anywhere to anywhere, any port'. Rule 2 says 'deny port 23'. Is Telnet blocked?

    Show the answer
    No. The first matching rule decides, and rule 1 matches everything. Rule 2 is never reached.

  3. Name three things you would switch off on a new router.

    Show the answer
    WPS, UPnP, remote administration from the internet (and Telnet, if it has it) — and change the default admin password.

  4. What does 'defence in depth' mean, in one sentence?

    Show the answer
    Several independent layers of protection, so that the failure of one does not expose the system.

Practise this in the lab

Remember
  • First matching rule wins; end with deny everything.
  • Allow what is needed, not block what is bad.
  • Hardening = switch off, tighten, update.
  • Many layers, and check from the outside.
