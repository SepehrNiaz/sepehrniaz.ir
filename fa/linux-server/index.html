اداره‌ی یک سرور لینوکس

کار روزانه‌ی یک مدیر سیستم: اتصال با SSH، نصب و به‌روزرسانی نرم‌افزار، راه‌اندازی سرویس‌ها، خواندن لاگ، فایروال و پشتیبان‌گیری.

بعد از این درس می‌توانی
  • با SSH و جفت کلید به سرور وارد شوی
  • با apt و systemctl نرم‌افزار نصب و سرویس‌ها را کنترل کنی
  • دلیل یک مشکل را در لاگ‌ها پیدا کنی
  • یک سرور جدید را در ساعت اولش ایمن کنی

چه چیزی یک کامپیوتر را سرور می‌کند؟

سرور نوع خاصی از دستگاه نیست. هر کامپیوتری است که کارش جواب‌دادن به درخواست کامپیوترهای دیگر است: دادن صفحه‌ی وب، نگه‌داشتن فایل، نگهداری پایگاه‌داده یا ضبط تصویر دوربین‌ها. معمولاً نمایشگر و صفحه‌کلید ندارد، شب و روز روشن است و از جای دیگری با ترمینال مدیریت می‌شود. پس هر چه تا اینجای مسیر یاد گرفتی — حرکت بین پوشه‌ها، فایل، مجوز، ابزارهای متن — دقیقاً همان چیزی است که اینجا استفاده می‌کنی. این درس پنج چیز جدید را اضافه می‌کند: دسترسی از راه دور، نرم‌افزار، سرویس، لاگ و محافظت.

اتصال از راه دور: SSH

SSH (شل امن) روی یک دستگاه دیگر، از طریق اتصالی رمزنگاری‌شده، ترمینال باز می‌کند. یک نام کاربری و آدرس سرور را می‌دهی؛ بعد از ورود، هر دستوری که تایپ کنی آنجا اجرا می‌شود، نه روی کامپیوتر خودت.

رمز را می‌شود حدس زد، پس حرفه‌ای‌ها به‌جایش با یک جفت کلید وارد می‌شوند. دو فایل می‌سازی: کلید خصوصی که هیچ‌وقت از کامپیوترت بیرون نمی‌رود و کلید عمومی که روی سرور می‌گذاری. سرور هر کس را که ثابت کند کلید خصوصی را دارد راه می‌دهد.

نرم‌افزار: مدیر بسته

در لینوکس نصب‌کننده را از سایت‌ها دانلود نمی‌کنی. سیستم فهرستی از نرم‌افزارهای آزموده به اسم «مخزن» دارد و یک «مدیر بسته» که از آن نصب می‌کند و همه‌چیز را به‌روز نگه می‌دارد. در اوبونتو و دبیان این ابزار apt است و در Red Hat، Rocky و Fedora ابزار dnf با همان مفاهیم.

دستورچه می‌کند
sudo apt updateتازه‌کردن فهرست (چیزی نصب نمی‌کند)
sudo apt upgradeنصب به‌روزرسانی‌های در انتظار
sudo apt install nginxنصب یک برنامه
sudo apt remove nginxحذف آن
apt search keywordجست‌وجوی یک برنامه
apt show nginxخواندن توضیحش قبل از نصب

سرویس: برنامه‌ای که در پس‌زمینه اجرا می‌شود

وب‌سرور یا پایگاه‌داده در ترمینال تو اجرا نمی‌شود؛ در پس‌زمینه به شکل «سرویس» اجرا می‌شود و سیستمی به اسم systemd آن را راه می‌اندازد و زیر نظر دارد. سرویس‌ها را با یک دستور کنترل می‌کنی: systemctl. دو مفهوم را باید جدا نگه داری: start (همین الان اجرا کن) و enable (بعد از هر راه‌اندازی دوباره خودکار اجرا کن). سرویسی که start شده ولی enable نشده بعد از راه‌اندازی بعدی دیگر نیست — دلیل معروفِ «دیروز کار می‌کرد».

لاگ: فهمیدن اینکه چه شد

وقتی سرویسی اجرا نمی‌شود حدس نزن — خودش قبلاً نوشته چرا. سیستم‌های جدید همه‌ی لاگ‌ها را در «ژورنال» جمع می‌کنند که با journalctl خوانده می‌شود؛ خیلی از برنامه‌ها هم فایل ساده زیر /var/log می‌نویسند که با ابزارهای متنِ درس قبل می‌خوانی‌شان.

چه کسی گوش می‌دهد؟ پورت‌ها

هر سرویس روی یک پورت شماره‌دار منتظر درخواست است. فهرست پورت‌های در حال گوش‌دادن نشان می‌دهد سرورت چه چیزی به شبکه ارائه می‌کند — و هر چیزی در این فهرست که نمی‌شناسی جای سؤال دارد.

فایروال

فایروال تعیین می‌کند دنیای بیرون به کدام‌یک از آن پورت‌ها می‌تواند برسد. در اوبونتو رابط ساده‌اش ufw است. ترتیبِ ایمن مهم است: اول SSH را مجاز کن و بعد فایروال را روشن کن — اگر برعکس انجام بدهی، خودت را از سرور خودت بیرون می‌اندازی.

ساعت اول روی یک سرور جدید

  • همه‌چیز را به‌روز کن: sudo apt update && sudo apt upgrade.
  • کاربر خودت را بساز و به گروه sudo اضافه کن؛ دیگر مستقیم با root کار نکن.
  • کلید SSH را نصب کن، مطمئن شو کار می‌کند و بعد ورود با رمز و ورود root را در /etc/ssh/sshd_config خاموش کن (PasswordAuthentication no و PermitRootLogin no) و ssh را دوباره راه بینداز.
  • فایروال را روشن کن و فقط چیزهای لازم را مجاز کن.
  • منطقه‌ی زمانی درست را تنظیم کن: sudo timedatectl set-timezone Asia/Tehran — لاگ با ساعت اشتباه بی‌فایده است.
  • به‌روزرسانی امنیتی خودکار را روشن کن: sudo apt install unattended-upgrades.
  • قبل از گذاشتن هر چیز باارزش روی دستگاه، پشتیبان‌گیری را راه بینداز.

پشتیبان‌گیری با rsync

وقتی سرور کند یا خراب است

سؤالدستور
پردازنده زیر فشار است؟uptime ; top
حافظه تمام شده؟free -h
دیسکی پر شده؟df -h ; du -sh /var/*
سرویسی از کار افتاده؟systemctl --failed
قبل از توقف چه گفته؟journalctl -u NAME -n 50
پورت باز است؟ss -tlnp
شبکه در دسترس است؟ping ; ip addr ; ip route

اشتباه‌های رایج

  • روشن‌کردن فایروال قبل از مجازکردن SSH.
  • start کردن سرویس و فراموش‌کردن enable.
  • خاموش‌کردن ورود با رمز قبل از اطمینان از کارکردن کلید — یک نشست را باز نگه دار و در نشست دیگر آزمایش کن.
  • کارکردن تمام‌روز با root.
  • نگه‌داشتن پشتیبان روی همان دیسکی که داده روی آن است.

تمرین

اول خودت امتحان کن، بعد جواب را باز کن.

  1. nginx را نصب کرده‌ای و کار می‌کند، ولی بعد از راه‌اندازی دوباره سایت قطع است. چه شده و راه‌حل چیست؟

    نمایش جواب
    سرویس start شده ولی enable نشده.
sudo systemctl enable --now nginx

  2. ۳۰ خط آخر لاگ سرویس ssh را نشان بده.

    نمایش جواب
    journalctl -u ssh -n 30

  3. ترافیک وب (۸۰ و ۴۴۳) را در ufw مجاز کن و نتیجه را بررسی کن.

    نمایش جواب
    sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw status

  4. پوشه‌ی /etc/nginx را از سرور 192.168.1.50 با کاربر sara روی دستگاه خودت کپی کن.

    نمایش جواب
    scp -r sara@192.168.1.50:/etc/nginx .

همین را در آزمایشگاه تمرین کن

یادت بماند
  • SSH با کلید درِ ورود است؛ از آن محافظت کن.
  • apt نصب می‌کند، systemctl اجرا می‌کند و journalctl توضیح می‌دهد.
  • start برای الان است و enable برای هر بار روشن‌شدن.
  • اول SSH را مجاز کن، بعد فایروال را روشن کن.
  • به‌روز کن، پشتیبان بگیر و بازگردانی را آزمایش کن.
