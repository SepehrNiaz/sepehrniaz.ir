خودکارسازی با اسکریپت‌های Bash

دنباله‌ای از دستورها را که هر روز تایپ می‌کنی به یک اسکریپت تبدیل کن که با یک کلمه اجرا می‌شود.

بعد از این درس می‌توانی
  • یک اسکریپت بنویسی، قابل اجرایش کنی و اجرا کنی
  • در اسکریپت از متغیر، خروجی دستورها و if استفاده کنی
  • با حلقه یک کار را برای چندین مورد تکرار کنی

یک اسکریپت Bash فقط یک فایل متنی پر از همان دستورهایی است که با دست تایپ می‌کنی، که از بالا به پایین اجرا می‌شوند. اگر کاری را بیش از دو بار انجام می‌دهی، ارزش اسکریپت‌کردن دارد. یک فایل با پسوند .sh بساز و با یک خط اول خاص شروعش کن.

اولین اسکریپتت

خط اول، که «شیبنگ» نام دارد، به سیستم می‌گوید کدام برنامه باید فایل را اجرا کند. بعد دستورها و توضیح‌ها (خط‌هایی که با # شروع می‌شوند) را اضافه می‌کنی.

اجرایش کن

یک بار با chmod فایل را قابل‌اجرا کن، بعد اجرایش کن. علامت $(…) یک دستور را اجرا می‌کند و خروجی‌اش را داخل خط تو می‌گذارد — اینجا، تاریخ امروز.

متغیرها و شرط‌ها

همیشه متغیرها را در گیومه‌ی دوتایی بگذار ("$host" نه $host). این تو را از باگ‌های عجیب وقتی یک مقدار فاصله دارد نجات می‌دهد.

چه وقت نوشتن اسکریپت می‌ارزد؟

یک قاعده‌ی ساده: بار سومی که همان مجموعه دستور را تایپ می‌کنی، آن را در یک فایل بگذار. اسکریپت کار را هر بار یک‌جور انجام می‌دهد، ساعت سه صبح، بدون جاانداختن یک قدم. اولین اسکریپت‌ها معمولاً پشتیبان‌گیری، پاک‌سازی، بررسی سلامت و نصب یک نرم‌افزار روی چند دستگاه است. برای پردازش سنگین متن یا هر چیزی بلندتر از حدود صد خط، پایتون معمولاً ابزار بهتری است.

آرگومان و پرسش

اسکریپت وقتی قابل استفاده‌ی دوباره می‌شود که مقدارهایش را از بیرون بگیرد. کلمه‌هایی که بعد از اسم اسکریپت تایپ می‌شوند به شکل $1، $2 و … می‌رسند؛ $# تعدادشان است، $@ همه‌ی آن‌هاست و $0 اسم خود اسکریپت. read موقع اجرا از کاربر سؤال می‌پرسد.

آزمون: پرسیدن سؤال بله یا نه

کروشه‌ها خودشان یک دستورند که بله یا نه جواب می‌دهد. بعد از [ و قبل از ] فاصله لازم دارند و برای مقایسه کلمه‌های مخصوص خودشان را دارند.

آزمونچه وقت درست است
[ -f file ]فایل وجود دارد
[ -d dir ]پوشه وجود دارد
[ -s file ]فایل وجود دارد و خالی نیست
[ -z "$a" ]متن خالی است
[ "$a" = "$b" ]دو متن یکی هستند
[ "$n" -eq 5 ]دو عدد برابرند (-ne نابرابر)
[ "$n" -gt 5 ]بزرگ‌تر (-ge حداقل، -lt کوچک‌تر، -le حداکثر)
[ ! -f file ]علامت ! هر آزمون را برعکس می‌کند

کد خروج: دستورها چطور نتیجه را گزارش می‌کنند

هر دستور با عددی تمام می‌شود که معمولاً نمی‌بینی. صفر یعنی کار انجام شد و هر عدد دیگر یعنی نشد. متغیر ویژه‌ی $? کد آخرین دستور را دارد: بعد از ls notes صفر است و بعد از ls nofile برابر ۲. دستور if به چیزی که چاپ شده نگاه نمی‌کند — به همین عدد نگاه می‌کند. اسکریپت‌های خودت هم باید همین قاعده را رعایت کنند: اگر همه‌چیز خوب بود exit 0 و اگر چیزی خراب شد exit 1 (یا عدد دیگر)، تا اسکریپت‌ها و زمان‌بندهای دیگر بفهمند.

حلقه روی فایل‌ها و روی خط‌ها

اسکریپتی که ایمن خطا می‌دهد

Bash به‌طور پیش‌فرض بعد از خطا ادامه می‌دهد و این می‌تواند خطرناک باشد: اگر cd خطا بدهد، rm بعدی در پوشه‌ی اشتباه اجرا می‌شود. سه تنظیم در ابتدای اسکریپت این را عوض می‌کند.

اجرای زمان‌بندی‌شده: cron

cron دستورها را در زمان‌های مشخص اجرا می‌کند. بنویس crontab -e و برای هر کار یک خط اضافه کن. خط با پنج بخش شروع می‌شود — دقیقه، ساعت، روز ماه، ماه، روز هفته — و ستاره یعنی «هر».

یک اسکریپت کامل: قبل از پرشدن دیسک خبرم کن

فهرست بررسی برای هر اسکریپت

  • خط اول #!/bin/bash و خط دوم توضیحی که بگوید اسکریپت چه می‌کند.
  • نزدیک ابتدای فایل set -euo pipefail.
  • همه‌ی متغیرها داخل نقل‌قول دوتایی.
  • آرگومان‌ها را بررسی کن و اگر نبودند یک خط راهنما چاپ کن.
  • اول با مقدارهای بی‌خطر آزمایش کن — قبل از اجرای واقعی rm، آن را با echo چاپ کن.
  • هر کاری را که انجام شد با تاریخ در لاگ بنویس.
  • هیچ‌وقت رمز را داخل اسکریپت ننویس؛ از یک فایل محافظت‌شده (chmod 600) بخوانش.

حلقه، آرگومان و کد خروج

هر دستور با یک کد خروج تمام می‌شود: صفر یعنی موفق و هر عدد دیگری یعنی ناموفق. if در واقع همین را بررسی می‌کند. اسکریپت کلمه‌هایی را که بعد از اسمش تایپ می‌شود هم می‌گیرد: $1 اولی، $2 دومی و $# تعدادشان است.

  • هنگام مقداردهی دور = فاصله نگذار: name="lab" درست است، نه name = "lab".
  • $(command) خروجی یک دستور را در متغیر می‌گذارد.
  • اسکریپت‌های جدی را با set -e شروع کن تا با اولین خطا متوقف شوند.
  • bash -x script.sh هر خط را موقع اجرا چاپ می‌کند — ساده‌ترین راه پیداکردن باگ.
  • برای اجرای هرشبه‌ی یک اسکریپت، با crontab -e یک خط اضافه کن.

اشتباه‌های رایج

  • گذاشتن فاصله دور علامت =.
  • جاانداختن فاصله‌های داخل [ ] — باید [ "$a" = "$b" ] باشد.
  • فراموش‌کردن نقل‌قول دور متغیرها که با اسم‌های فاصله‌دار خراب می‌شود.

تمرین

اول خودت امتحان کن، بعد جواب را باز کن.

  1. خط اول یک اسکریپت Bash باید چه باشد؟

    نمایش جواب
    #!/bin/bash

  2. تاریخ امروز را (به شکل YYYY-MM-DD) در متغیری به اسم today بگذار.

    نمایش جواب
    today=$(date +%Y-%m-%d)

  3. حلقه‌ای بنویس که اسم همه‌ی فایل‌های .log این پوشه را چاپ کند.

    نمایش جواب
    for f in *.log; do
  echo "$f"
done

  4. موقع اجرای ./backup.sh پیام «Permission denied» می‌گیری. چرا؟

    نمایش جواب
    هنوز قابل اجرا نیست: chmod +x backup.sh

همین را در آزمایشگاه تمرین کن

یادت بماند
  • اسکریپت همان دستورهایی است که بلدی، ذخیره‌شده در یک فایل.
  • کد خروج صفر یعنی موفق و if دقیقاً همین را بررسی می‌کند.
  • متغیرها را داخل نقل‌قول بگذار و با bash -x آزمایش کن.
